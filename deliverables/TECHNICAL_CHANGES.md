## 1. Executive Summary

This document provides a comprehensive technical breakdown of the architectural overhaul, bug fixes, formatting standardization, and visual enhancements implemented in the **OsdagBridge** LaTeX report generation system. 

The primary objectives achieved in this refactoring are:
1. **Repeated Table Headers Across Page Breaks:** Migration of all multi-page tables across Chapters 2, 3, 4, 5, and 7 to compliant LaTeX `longtable` implementations equipped with standard pagination semantics (`\endfirsthead`, `\endhead`, `\endfoot`, and `\endlastfoot`).
2. **Layout Calibration & Footer Margin Bleed Resolution:** Permanent resolution of vertical spacing anomalies, specifically the Page 29/30 footer overlap where Table 5.12 (`Girder Design Summary`) row "G4" and note bled into the page footer rule. Fixed via geometry calibration (`top=25mm, bottom=28mm, footskip=16pt, headheight=20pt`), eradication of negative `\vspace` footrule shifts, and `\needspace{8\baselineskip}` page-break protection.
3. **Load & Geometry Table Refactoring (Chapter 3):** Clean physical separation of Vehicle Live Loads (IRC 6:2017) and Footway/Footpath Live Loads into distinct tables, featuring multi-level hierarchical headers for vehicle parameters, impact factors, and braking loads.
4. **Utilization Ratio (UR) Summary Visualizations (Section 5.5):** Fully automated, programmatic Matplotlib visualization suite generating 4 publication-quality bar charts for Steel Plate Girders, Concrete Deck Slab, Cross Bracing, and End Diaphragms, featuring an explicit red dashed threshold line at the allowable limit ($UR = 1.0$).
5. **Material Quantity Visualizations (Chapter 7):** Automated generation of Bill of Materials (BOM) bar charts illustrating (a) Structural steel tonnage breakdown by component (Girders, Cross Bracing, End Diaphragms) and (b) Concrete deck volume ($m^3$) vs. Reinforcement steel weight ($MT$).
6. **Centralized Style Architecture (SSOT):** Establishment of `styles.py` (`osdagbridge.core.reports.styles`) as the authoritative Single Source of Truth for all report styling, colors, geometries, typography, table paddings, and chart visual themes.

## 3. Architecture & Style System (SSOT: `styles.py`)

Prior to this refactoring, styling parameters (geometry, margins, table padding, colors, header/footer commands) were duplicated or hardcoded across multiple generator files. We designed and implemented `src/osdagbridge/core/reports/styles.py` to serve as the unified Single Source of Truth (SSOT).

### 3.1 Color Palette Definitions
Defined standard brand, structural, status, and chart color constants using hexadecimal codes matching Osdag's visual identity:
* `COLOR_OSDAG_GREEN = "#91B014"` (Osdag brand identity)
* `COLOR_DARK_SLATE = "#2C3E50"` (Primary text, chart axes, boundaries)
* `COLOR_TABLE_HEADER_BG = "#EAECEE"` (Subtle contrasting table header background)
* `COLOR_TABLE_ALT_ROW = "#F8F9FA"` (Alternating zebra row shading)
* `COLOR_PASS = "#27AE60"` (Passing design check bars, $UR \leq 1.0$)
* `COLOR_FAIL = "#C0392B"` (Failing design check bars, $UR > 1.0$)
* `CHART_THRESHOLD = "#E74C3C"` (Critical limit threshold line at $UR = 1.0$)
* `CHART_BAR_STEEL = "#2980B9"`, `CHART_BAR_CONCRETE = "#7F8C8D"`, `CHART_BAR_REBAR = "#D35400"`

### 3.2 Geometry & Layout Calibration (`get_geometry_latex()`)
Resolved strict geometry requirements to prevent page boundary bleeding:
```latex
\usepackage[
    a4paper,
    top=25mm,
    bottom=28mm,
    left=20mm,
    right=20mm,
    headheight=20pt,
    headsep=12pt,
    footskip=16pt
]{geometry}
```
* **Bottom Margin:** Increased to 28 mm with an explicit 16 pt `footskip`, providing an inviolable boundary between table content and the running footer.
* **Headheight:** Set to 20 pt with 12 pt separation to accommodate multi-line running headers without LaTeX `fancyhdr` warnings.

### 3.3 Typography & Table Layout Rules (`get_spacing_preamble_latex()`)
* Standardized `\setstretch{1.15}` for optimal document readability.
* Standardized `\setlength{\tabcolsep}{6pt}` and `\renewcommand{\arraystretch}{1.15}` for uniform, professional cell breathing space.
* Configured `\setlength{\LTpre}{2pt}` and `\setlength{\LTpost}{6pt}` to prevent excessive white space around `longtable` environments.
* Added `\BeforeBeginEnvironment{longtable}{\needspace{6\baselineskip}}` globally, preventing orphaned table titles at the bottom of pages.

### 3.4 Header & Footer Theme (`get_fancyhdr_latex()`)
* **Elimination of Negative Vertical Space:** Removed the historical `\vspace{-8pt}` hack in `\footrule` that pulled the footer line into the text block.
* Standardized `firstpage`, `plain`, and `main` pagestyles with 1 pt Osdag green accent rules and standardized metadata (`Project Name | Job Number` in header, `Osdag | FOSSEE | IIT Bombay` and `Page X of Y` in footer).

## 4. Detailed Component Changes & File Modifications

### 4.1 Chapter 5: Design Checks (`src/osdagbridge/core/reports/chap5.py`)
Chapter 5 is the largest and most complex module in the report, containing 30 individual structural check tables (Tables 5.1 through 5.22/5.30).
* **Repeated Headers Across All 30 Tables:** 
  Every single `longtable` was refactored with the standard 4-block header/footer protocol:
  1. `\endfirsthead`: First page caption and bold column headers.
  2. `\endhead`: Continuation caption (`\caption[]{\textbf{...} \textit{(Continued from previous page)}} \\`) and repeated bold column headers on all subsequent pages.
  3. `\endfoot`: Table transition rule with right-aligned `\multicolumn{N}{r}{\textit{\footnotesize Continued on next page...}} \\`.
  4. `\endlastfoot`: Terminal `\hline` marking table completion.
* **Fix for Page 29/30 Footer Bleed (Table 5.12):**
  Added `\needspace{8\baselineskip}` immediately preceding Table 5.12 (`Girder Design Summary (DCR / Utilization Ratio)`). This guarantees that if fewer than 8 lines remain on the current page, the entire summary table shifts cleanly to the next page. Combined with the 28 mm bottom margin and 16 pt footskip, row "G4" and the concluding note now render with generous clearance above the footer rule.
* **Dynamic UR Visualization Embedding (Section 5.5):**
  Added Section 5.5.1 (`Component Utilization Ratio (UR) Summary Visualizations`). When `fig_paths` is provided (or generated dynamically on the fly), a high-resolution $2 \times 2$ grid of subfigures is dynamically rendered in LaTeX (`figure[H]`), visualizing Utilization Ratios with the red dashed $UR=1.0$ limit line for:
  - (a) Steel Plate Girders (Moment, Shear, LTB, Deflection, Stress, Fatigue)
  - (b) Concrete Deck Slab (Transverse Shear, Crack Width, Sagging Flexure, Hogging Flexure, Overhang, Punching Shear, One-Way Shear)
  - (c) Cross Bracing Members (Compression, Tension, Slenderness)
  - (d) End Diaphragm Members (Compression/Moment, Tension/Shear)

### 4.2 Chapter 7: Material Take-Off & Quantities (`src/osdagbridge/core/reports/chap7.py`)
* **Table 7.1 Refactoring:**
  Replaced uncaptioned floating syntax with a fully standard `longtable` utilizing `\caption{\textbf{Bill of Materials...}}\label{tab:bom} \\`, `\endfirsthead`, `\endhead`, `\endfoot`, and `\endlastfoot`.
* **Material Quantity Visualizations Embedding:**
  Added Section 7.2 (`Material Quantity Visualizations`) embedding a 2-subfigure block (`figure[H]`):
  - (a) Structural Steel Tonnage Breakdown by Component (Girders, Cross Bracing, End Diaphragms)
  - (b) Concrete Volume ($m^3$) vs. Reinforcement Steel Weight ($MT$)

### 4.3 Chapter 3: Loads & Load Combinations (`src/osdagbridge/core/reports/chap3.py`)
* **Separation of Live Loads:** Split the previous combined live load representation into two distinct, dedicated tables:
  - **Table 3.3:** `Vehicle Live Loads (LL) — per IRC 6:2017`, featuring multi-level hierarchical column headers (`\multicolumn{3}{c|}{\textbf{Braking Load}}` with sub-columns `Considered?`, `Value (kN)`, `Eccentricity (m)`).
  - **Table 3.4:** `Footway / Footpath Live Load (per IRC 6:2017 Cl. 206)`, explicitly presenting footpath provision status, design mode, reference clause, applied intensity ($kN/m^2$), and total design force.
* **Pagination Protocols:** Added `\endfirsthead`, `\endhead`, `\endfoot`, and `\endlastfoot` across all Chapter 3 tables (Dead Load, SIDL, Wind Load, Seismic Load, Thermal Load).

### 4.4 Chapter 2: Input Parameters (`src/osdagbridge/core/reports/chap2.py`)
* Converted all 9 input parameter tables to compliant repeated-header `longtable`s:
  - Table 2.1: Typical Cross-Section & Environmental Inputs
  - Table 2.2: Bridge Components & Material Specifications
  - Table 2.3: Plate Girder General Information
  - Table 2.4: Plate Girder Dimensions & Plate Thicknesses
  - Table 2.5: Plate Girder Restraint & Lateral Support Conditions
  - Table 2.6: Cross Bracing Geometry & Profile Details
  - Table 2.7: End Diaphragm Geometry & Section Details
  - Table 2.8: Shear Connector Configuration & Mechanical Properties
  - Table 2.9: Partial Safety Factors for Materials & Limit States

### 4.5 Chapter 4: Analysis Results (`src/osdagbridge/core/reports/chap4.py`)
* Added full pagination headers (`\endfirsthead`, `\endhead`, `\endfoot`, `\endlastfoot`) to:
  - Table 4.1: Summary of Maximum Demands (Governing Load Combinations)
  - Table 4.2: Reactions at Supports (Pier / Abutment)
  - Table 4.3: Maximum Deflection Summary (SLS Frequent Combination)

### 4.6 Orchestration & Engine (`src/osdagbridge/core/reports/report_generator.py`)
* **SSOT Wiring:** Updated `preamble()` to source all geometry, spacing, colors, and header/footer logic from `styles.py`.
* **Automated Visualization Pipeline:** In `generate_report()`:
  - Programmatically computes material quantities via `calculate_material_quantities()`.
  - Automatically synthesizes the two Chapter 7 charts (`material_takeoff_steel_tonnage.png`, `material_takeoff_concrete_rebar.png`) into `tmp_dir/images`.
  - Automatically synthesizes the four Chapter 5 UR charts (`ur_summary_girders.png`, `ur_summary_deck.png`, `ur_summary_bracing.png`, `ur_summary_diaphragms.png`) into `tmp_dir/images`.
  - Injects relative image paths into `fig_paths` and passes them down to `ch5_design_checks()` and `ch7_quantities()`.
* **Robust Compiler Discovery:** Implemented an automatic compiler discovery fallback:
  - Discovers `pdflatex` or standalone `tectonic.exe` (`D:\IIT Boumby\tectonic_bin\tectonic.exe` or on PATH).
  - Automatically selects `tectonic` when `pdflatex` is not installed on the host OS, ensuring seamless one-command report compilation.
